# AI Analysis — Prompt & Call Logic (signal-only step)

How `worker.main` builds the signal-only prompt (`worker/prompt.py`) and calls Claude
(`worker/claude_cli.py`). The news step (`prompt_news.py`) reuses the same data sections;
the final step (`prompt_final.py`) has its own prompt. No caching or scheduling here.

## Inputs

Per ticker, the history-sheet rows parsed by `analytics.parse_csv`:
`{date, signal, price, strength, confidence, adx, regime, rsi, plus_di, minus_di, earnings}`
(the last five come from the sheet's extra columns I–L and O and are empty on older rows).

- `consensus` — BUY/SELL/HOLD counts across latest signals
- `signal_changes` — tickers whose signal changed vs. their previous row (`"TICK: PREV→NEW"`)
- `port_line` — equal-weight strategy % vs buy-and-hold %
- `snapshot_lines` — one line per ticker (format below)
- `fwd_line` — historical avg next-trading-day return per signal type
- `today` — ISO date string
- `picks` / `risks` — the tickers `selection.select` fixed for topPicks/riskWatch, each with
  its rule hits (see README "Three analyses")

## Prompt template

```
You are reviewing algorithmic stock signals generated by a systematic trading bot. Today is {today}.

How the signals work (trend-following, daily close data):
- BUY = price above its 200-day average (regime=UP), 20-day EMA above 50-day EMA, and +DI above -DI.
- SELL = trend broken: price below the 200-day average (regime=DOWN), or short-term trend and DI both turned down.
  It means "exit / stay out", not a prediction of how far the stock will fall.
- HOLD = long-term uptrend intact but short-term trend mixed.
- agree% = how many of 5 trend reads point the same way (20/60/100 = 3/4/5 of 5). It is NOT a win probability.
- ADX = trend strength regardless of direction; di=+X/-Y shows the direction (+DI vs -DI).
- earn=in Nd = next earnings report in N calendar days (earn=- when none within 14 days or unknown).
  The price can gap on the report in either direction; the trend signal cannot anticipate it.
- Backtests show this system's value is risk control (smaller drawdowns), not predicting which stocks beat
  the market: its BUY vs SELL forward returns are close to a coin flip. Frame conclusions accordingly.

Portfolio: {n} tickers | BUY: {BUY} | SELL: {SELL} | HOLD: {HOLD}
Signal changes since yesterday: {changes}        (or "No signal changes since yesterday.")

Portfolio performance (equal-weight simulation):
{port_line}

Current snapshot (ticker | signal | price | streak | period_return | agree% | ADX | regime/DI | earnings | completed trades, win rate, expectancy):
{snapshot_lines}

Signal effectiveness — avg next-trading-day % return across all historical data:
{fwd_line}

The tickers below were already selected by fixed rules from the snapshot above (the rule
hits are shown after each). Do not add, drop or reorder them — your job is to explain them.

topPicks (BUY tickers in an uptrend; "clean" = regime=UP, +DI at least 5 above -DI, ADX >= 20,
agree >= 60; "weak" falls short of one of those, as listed):
  - {TICK}: {rule hits}                 (or "(none — ...)")

riskWatch (broken, weakening or unreliable trends, earnings soon):
  - {TICK}: {rule hits}

Respond with ONLY this JSON object (no markdown fences, no text outside the JSON):
{ "generatedAt": ..., "marketSummary": ..., "topPicks": [...], "riskWatch": [...], "portfolioNote": ... }

Rules:
- topPicks and riskWatch: exactly the tickers listed above, in that order, one reason each.
  An empty list above means an empty array.
- A "weak" topPick's reason must say what it falls short on (e.g. ADX below 20 = weak trend
  strength). These are trends to follow, not forecasts of outperformance.
- A riskWatch reason should explain the rule hits with the ticker's figures (streak, regime,
  DI, agree%, ADX).
- If tickers that share a theme (e.g. several semiconductor names) are all SELL, say so in
  marketSummary or portfolioNote as one theme rather than as separate risks.
- Ignore win rate / expectancy for tickers marked "too few to judge" — never cite them as evidence.
- If a ticker you mention has earn=in Nd with N <= 7, say so in its reason (the trend read carries
  event risk until the report is out). Do not treat an upcoming report as bullish or bearish by itself.
- Be specific (ticker names, streak lengths, agree%, ADX, DI, % figures) and avoid overconfident language
  ("will rise", "guaranteed") — describe trend and risk, not certainty.
- Do not invent data not present above.
```

## Snapshot line format

Fields joined with `" | "`:

```
ticker.ljust(5)
signal.ljust(4)
"$" + f"{price:.2f}".rjust(8)
f"streak={signal}×{days}d".ljust(14)
f"period={sign}{period_change_pct:.1f}%".ljust(14)
"agree=" + f"{confidence:.0f}".rjust(3)
"adx=" + f"{adx:.0f}".rjust(3)
f"regime={regime} di=+{plus_di:.0f}/-{minus_di:.0f}"     ("regime=? di=?" when missing)
"earn=in {days}d" when column O is 0-14 days after today, else "earn=-"
trade stats:
  0 completed trades        -> "trades=0"
  1-4 (MIN_TRADES_FOR_STATS) -> "trades=N (too few to judge)"
  5+                         -> "trades=N wr=XX% exp=+X.X%"
```

Example:

```
AAPL  | BUY  | $  342.37 | streak=BUY×3d  | period=+35.7%  | agree= 60 | adx= 17 | regime=UP di=+27/-24 | earn=- | trades=2 (too few to judge)
NVDA  | SELL | $  186.64 | streak=SELL×8d | period=+1.9%   | agree= 60 | adx= 29 | regime=DOWN di=+10/-42 | earn=in 9d | trades=6 wr=0% exp=-4.6%
```

`fwd_line`: `BUY: +0.061% (n=1150) | SELL: +0.047% (n=901) | HOLD: +0.088% (n=780)`

## Call

`claude -p --output-format json --model $CLAUDE_MODEL --tools "" --json-schema <ANALYSIS_JSON_SCHEMA>
--system-prompt <SYSTEM_PROMPT> --strict-mcp-config --disable-slash-commands --setting-sources ""`
(model default `claude-sonnet-5-5`), prompt piped via stdin, run from an empty temp directory
(see `claude_cli.py` docstring for why). The last four flags replace Claude Code's own
system prompt and skip MCP connectors, skills and settings — about 20k input tokens a call
that don't apply here (24.8k → 5.2k measured 2026-11-09). The response is then checked by
`quality.check_analysis`; on any issue the prompt is re-sent once with the previous answer and
the list of problems appended (`claude_cli.run_checked`), and leftovers are stored as
`qualityIssues`. The
response's `structured_output` must match:

```
{ generatedAt: str, marketSummary: str,
  topPicks:  [{ticker: str, reason: str}],
  riskWatch: [{ticker: str, reason: str}],
  portfolioNote: str }
```
